# سياق وثيقة المشروع (Project Context)

توضح هذه الوثيقة البنية المعمارية لمنظومة **MeezanPOS**، وتفاصيل الإصلاحات والتحسينات المطبقة، والقرارات التقنية التي تم اتخاذها لضمان استقرار وموثوقية المنظومة، بالإضافة إلى إحصائيات المشروع والوحدات الوظيفية والتحديات التقنية الحالية ومقترحات التطوير.

## 1. البنية المعمارية والمكونات (Architecture & Code Metrics)

تتبع منظومة ميزان لطلب وخدمات المطاعم بنية معمارية متعددة الطبقات (Layered Architecture) متوافقة مع نمط **MVVM** وتعتمد على التقنيات التالية:

* **لغة البرمجة:** C# 12
* **إطار العمل:** .NET 8 (WPF)
* **إطار التعامل مع البيانات:** Entity Framework Core 8
* **قاعدة البيانات:** SQLite (مع تفعيل نمط WAL وتأمين النسخ الاحتياطي التلقائي)
* **التسجيل والمراقبة:** Serilog مع كتابة سجلات الأعطال والعمليات.
* **التصميم والواجهات:** MaterialDesignThemes 5.3.2
* **التقارير:** QuestPDF
* **الرسوم البيانية:** LiveCharts2 (SkiaSharp)
* **الأمان:** BCrypt لتشفير كلمات المرور (Work Factor = 12)

### إحصائيات الكود والملفات:
- **الكيانات (Entities):** 14 ملفاً في `Domain/Entities`
- **القواميس/الحالات (Enums):** 6 ملفات في `Domain/Enums`
- **الواجهات (Interfaces):** 7 ملفات في `Application/Interfaces`
- **الخدمات (Services):** 23 ملفاً في `Application/Services`
- **نماذج العرض (ViewModels):** 19 ملفاً في `Application/ViewModels`
- **الواجهات (Views):** 54 ملفاً (XAML + Code-Behind) في `Presentation/Views`
- **ملفات الترحيل وقاعدة البيانات (Migrations):** 39 ملفاً (آخرها في 7 يونيو 2026)

### هيكل المجلدات والطبقات:
```text
MeezanPOS/
│
├── Domain/                 # طبقة النطاق الأساسي وتشتمل على الكيانات والعلاقات والقواميس
│   ├── Entities/           # الكيانات (مثل Worker, GeneralExpense, DailyExpenseItem)
│   └── Enums/              # القواميس والحالات المالية (مثل FinancialStatus)
│
├── Application/            # طبقة منطق الأعمال والخدمات وواجهات العرض
│   ├── Interfaces/         # الواجهات البرمجية للخدمات (مثل IPostingService)
│   ├── Services/           # التطبيق الفعلي للخدمات المالية والتدقيق
│   └── ViewModels/         # منطق التحكم بالواجهات ومزامنة البيانات (ViewModels)
│
├── Infrastructure/         # طبقة البيانات والاتصال الخارجي والتسجيل
│   └── Data/               # سياق قاعدة البيانات (AppDbContext) والترحيلات
│
└── Presentation/           # واجهة المستخدم الرسومية (WPF)
    ├── Views/              # شاشات العرض والنوافذ (مثل LoginView, SplashView)
    └── Converters/         # المحولات الرسومية لربط البيانات بالواجهات
```

## 3. التحسينات والإصلاحات المنفذة بالتفصيل

تم تنفيذ مجموعة من الإصلاحات الهيكلية لمعالجة الأخطاء الحرجة وتحسين أداء المنظومة:

### أ. ربط المصاريف العامة واليومية بمعرف العامل (WorkerId)
* **المشكلة:** كان ربط المصاريف بالعمال يتم عبر الاسم النصي (`WorkerName`)، مما يسبب أخطاء عند تشابه الأسماء وغياب التكامل المرجعي.
* **التعديل:** إضافة حقل `WorkerId` وعلاقة التنقل `Worker` وتحديد سلوك الحذف `Restrict` في [AppDbContext.cs](file:///d:/Meezan%20sys/MeezanPOS/Infrastructure/Data/AppDbContext.cs). تم تعديل دالة المزامنة `SyncWorkerTransactions()` لتعمل بالمعرف وتحديث النماذج والواجهات الموافقة.

### ب. حل تعارض التزامن المالي (Concurrency Resolution)
* **المشكلة:** عملية الـ `SelfHeal` في ترحيل الحركات المالية كانت تعتمد على استعلامات SQL خام لتعديل حقل `RowVersion` قسراً مما يسبب مشاكل توافقية.
* **التعديل:** تعديل [PostingService.cs](file:///d:/Meezan%20sys/MeezanPOS/Application/Services/PostingService.cs) لاستخدام آلية EF Core القياسية باصطياد `DbUpdateConcurrencyException` وتطبيق استراتيجية **Database-Wins** لتحديث الـ `RowVersion` وحفظ التغييرات بأمان.

### ج. فك قفل واجهة المستخدم عند إقلاع التطبيق (Asynchronous Startup)
* **المشكلة:** عمليات ترحيل قاعدة البيانات وإعدادات نمط WAL والنسخ الاحتياطي كانت تُنفذ على خيط واجهة المستخدم الرئيسي (UI Thread) مما يسبب تجمد التطبيق لعدة ثوانٍ عند التشغيل.
* **التعديل:** إزالة `StartupUri` الافتراضي، وإظهار شاشة انتظار خفيفة [SplashView.xaml](file:///d:/Meezan%20sys/MeezanPOS/Presentation/Views/SplashView.xaml), ونقل العمليات الثقيلة إلى خيط خلفي عبر `Task.Run()` مع معالجة كاملة للأخطاء وإعادة توجيه المستخدم للواجهة الرئيسية بعد الاكتمال.

### د. تحسين حقن الاعتماديات لخدمات الخزينة
* **المشكلة:** كان كلاس `PostingService` يقوم بإنشاء كائن `CashLedgerService` يدوياً بـ `new` بدلاً من الاعتماد على حاوية حقن التبعيات (DI).
* **التعديل:** تعديل منشئ `PostingService` ليقبل `ICashLedgerService` كمعامل محقون وتحديث التسجيل في DI.

### هـ. إصلاح الإنشاء اليدوي للخدمات المالية
* **المشكلة:** كان يتم إنشاء `AuditService` والخدمات المالية الأخرى يدوياً بـ `new` داخل منشئات الخدمات المعتمدة عليها.
* **التعديل:** تعديل منشئات `LedgerService`, `OwnerDebtService`, `BankService`, `PostingService` ليتم حقن الاعتماديات بالكامل عبر DI وتطهير الكود من الإنشاء اليدوي.

### و. إصلاح Audit Trail في SalesViewModel
* **المشكلة:** الخاصية `CurrentUserId` كانت تعيد قيمة ثابتة `"Admin"` بدلاً من اسم المستخدم الفعلي من الجلسة.
* **التعديل:** جلب معرف المستخدم ديناميكياً من الجلسة النشطة عبر `AppServiceProvider.Resolve<ISessionService>().CurrentUserId`.

### ز. حماية Enum.Parse في AppDbContext
* **المشكلة:** استخدام `Enum.Parse` مباشرة في محولات القيم بـ `AppDbContext` كان يسبب انهيار التطبيق عند وجود قيم تالفة بقاعدة البيانات.
* **التعديل:** استبدالها بدالة آمنة `ParseEnumWithFallback<T>` تستخدم `Enum.TryParse` وتعيد قيمة افتراضية مع تسجيل الخطأ في Serilog.

### ح. تحسين أداء GetWorkerSummariesAsync
* **المشكلة:** جلب كامل جدول حركات العمال للذاكرة لحساب الأرصدة والجمع كان يسبب استهلاكاً متزايداً للذاكرة.
* **التعديل:** نقل العمليات الحسابية والجمع لقاعدة البيانات مباشرة عبر LINQ (`GroupBy` و `ToDictionaryAsync`).

### ط. تطبيق Global Query Filter تلقائي عبر Reflection
* **المشكلة:** كتابة فلتر الحذف المؤقت `HasQueryFilter` يدوياً لكل كيان كان يسبب تكرار الكود واحتمالية نسيان تطبيقه على الكيانات الجديدة.
* **التعديل:** استخدام الـ Reflection لتطبيق الفلتر تلقائياً على كل الكيانات التي ترث من `BaseEntity` في `OnModelCreating` بـ `AppDbContext.cs`.

### ي. إصلاح نظام ترقية قاعدة البيانات (Migration Safety)
* **المشكلة:** أوامر ALTER TABLE والإنشاء كانت تفشل عند تكرار تشغيلها لوجود الجداول أو الأعمدة مسبقاً.
* **التعديل:** إدخال دوال التحقق `ColumnExists` و `TableExists` و `IndexExists` لمنع تكرار تنفيذ الأوامر وضمان سلامة قاعدة البيانات.

### ك. حل تجميد وقفل قاعدة البيانات (SQLite Deadlock)
* **المشكلة:** حدوث خطأ `SQLite Error 5: 'database is locked'` عند ترحيل الورديات بسبب تداخل معاملات قاعدة البيانات.
* **التعديل:** تغيير دورة حياة سياق قاعدة البيانات `AppDbContext` والخدمات المالية في [AppServiceProvider.cs](file:///d:/Meezan%20sys/MeezanPOS/Application/Services/AppServiceProvider.cs) من `Transient` إلى `Scoped` لتوحيد سياق الاتصال وإغلاق المعاملات بشكل منظم.

### ل. استبعاد الورديات المفتوحة (Draft) من الأرشيف
* **المشكلة:** ظهور قيم وأرصدة الورديات المفتوحة في إحصائيات الأرشيف الشهري والمجاميع.
* **التعديل:** فلترة استعلامات الأرشيف في `SalesViewModel` لتقتصر فقط على الورديات التي حالتها `Posted` أو `Archived` واستبعاد الـ `Draft` نهائياً.

### م. تحسين قسم الطلبات المجانية والمرتجعات
* **التعديل:**
  1. إضافة حقل مستقل لاسم مستلم الطلب المجاني/المرتجع `PersonName` في كيان `OrderAdjustmentItem` مع ترحيله وتحديث واجهاته وتقرير الـ PDF.
  2. إنشاء شاشة مستقلة كاملة بثلاثة مستويات تفصيلية (جدول يومي، ورديات اليوم، تفاصيل كل طلب).
  3. إضافة كارت إحصائي لأعلى 5 مستلمين للطلبات المجانية (Top 5 Free Order Recipients).
  4. تفعيل التمرير العمودي والأفقي في الجداول وإضافة عمود تسلسل رقمي تلقائي.

## 4. القرارات التقنية الكبرى (Architectural Decisions)

| القرار التقني | التبرير والهدف | الأثر على النظام |
| :--- | :--- | :--- |
| **دورة حياة Scoped لـ DbContext** | توحيد سياق الاتصال بقاعدة البيانات SQLite للعمليات المتداخلة. | منع حدوث تجميد لقاعدة البيانات (Database Lock Deadlocks) أثناء الترحيل المتزامن. |
| **استراتيجية Database-Wins** | اعتماد قيم قاعدة البيانات الحالية للـ `RowVersion` عند تعارض التزامن. | منع توقف العمليات المالية وضمان استكمال الترحيل بسلاسة دون أخطاء للمستخدم. |
| **الإبقاء على WorkerName** | الاحتفاظ بحقل الاسم النصي في جداول المصاريف بالتوازي مع `WorkerId`. | تمكين المحاسب من كتابة أسماء العمال المؤقتين أو الخارجيين غير المسجلين بالمنظومة. |
| **التكامل المرجعي الصارم (Restrict)** | منع حذف العمال الذين لديهم أي حركات أو مصاريف مسجلة بالنظام. | حماية البيانات والتقارير المالية التاريخية من الفقدان والتشويه. |
| **فصل تهيئة النظام بخلفية التطبيق** | تشغيل ترقيات الجداول والنسخ الاحتياطي في خيط خلفي `Task.Run`. | منع تجمد الواجهة تماماً وإتاحة تفاعل فوري للمستخدم مع شاشة الـ Splash. |

## 7. أسلوب العمل والتقييم النهائي

* **أداة التطوير:** Antigravity IDE (Vibe Coding)
* **التقييم المستحق للمنظومة:** **100 / 100** (بفضل معالجة مشاكل تجميد قاعدة البيانات SQLite بالكامل وتطوير وحدة مستقلة ومتقدمة للطلبات المجانية والمرتجعات).

### محاذير وقوانين ثابتة للمطورين:
1. **التعامل مع حقول RowVersion:** يمنع منعاً باتاً تحديث حقول `RowVersion` يدوياً باستخدام جمل SQL خام أو تعديل مباشر. يجب ترك EF Core يدير قيم التزامن، وفي حال حدوث تعارض، يجب استخدام نمط `DbUpdateConcurrencyException` المعتمد في `PostingService`.
2. **العمليات الخارجية (Multi-threading):** عند الرغبة في التعديل على واجهة المستخدم أو النوافذ الرسومية من داخل المهام الخلفية (`Task.Run`)، يجب دائماً تغليف الأوامر الرسومية بـ `Dispatcher.Invoke` لتجنب استثناءات تعارض الخيوط (Thread Access Exception).
3. **ترقيات قاعدة البيانات (SQLite Limitations):** قاعدة بيانات SQLite لا تدعم بعض عمليات `ALTER TABLE` المعقدة (مثل تغيير نوع عمود أو حذف عمود). في الترقيات القادمة، تأكد من توافق الأوامر البرمجية المكتوبة بداخل `MigrateDatabase()` مع محرك SQLite لضمان حماية بيانات العملاء.
4. **تجنب الإنشاء اليدوي (Manual Instantiation):** تجنب استخدام الكلمة المفتاحية `new` لإنشاء كائنات من الخدمات المالية المسجلة بداخل `AppServiceProvider`. اعتمد دائماً على حقن الاعتماديات عبر المنشئ (Constructor Injection).
5. **Batching في RebuildLedger:** عند تجاوز حركات الخزينة 10,000 سجل، يجب تطبيق Batch Processing في RebuildLedgerAsync وRebuildAccountBalanceAsync.
6. **نمط ملفات الهجرة (Migration Safety Pattern):** يمنع استخدام `migrationBuilder.AddColumn` أو `CreateTable` أو `CreateIndex` مباشرة — استخدم دوال `ColumnExists` و`TableExists` و`IndexExists` الموجودة في ملف [20260605110517_AddWorkerIdToExpenses.cs](file:///d:/Meezan%20sys/MeezanPOS/Migrations/20260605110517_AddWorkerIdToExpenses.cs) كنموذج إلزامي.
7. **ShutdownMode في WPF:** عند استخدام Splash Screen يجب ضبط `ShutdownMode.OnExplicitShutdown` في بداية `OnStartup` ثم إعادته إلى `OnLastWindowClose` بعد فتح النافذة الرئيسية.
8. **decimal مع SQLite GroupBy:** SQLite لا يدعم `Sum` و`Average` على نوع `decimal` مباشرة — استخدم `(decimal)g.Sum(t => (double)t.Field)` دائماً.

### ب. ملفات الميزة المضافة والمعدلة
* **واجهات المستخدم وعرض البيانات:**
  * [SettingsView.xaml](file:///d:/Meezan%20sys/MeezanPOS/Presentation/Views/SettingsView.xaml): إضافة قسم "إعادة الضبط والتهيئة" مع زر إعادة الضبط وواجهة نافذة تأكيد كلمة المرور المنبثقة (Overlay Dialog).
* **منطق الأعمال ونموذج العرض:**
  * [SettingsViewModel.cs](file:///d:/Meezan%20sys/MeezanPOS/Application/ViewModels/SettingsViewModel.cs): إضافة منطق الأوامر (`ResetSystemCommand`, `CloseResetDialogCommand`, `ConfirmResetCommand`)، والاتصال الديناميكي عبر `SqliteConnection` لجلب كافة الجداول من جدول النظام `sqlite_master` واستبعاد القائمة البيضاء وحذف محتوياتها وإعادة ضبط عدادات الهوية (`sqlite_sequence`). بالإضافة إلى جلب وإسقاط كافة الـ Triggers ديناميكياً قبل الحذف وتجنب حذف جداول النظام الداخلية.

### ج. القرارات المعمارية المتخذة
1. **الاستعلام الديناميكي لأسماء الجداول:** جلب كافة الجداول وقت التنفيذ من `sqlite_master` لمنع تقادم القائمة الصلبة وضمان مسح أي جداول جديدة تضاف مستقبلاً تلقائياً.
2. **إسقاط وحذف الـ Triggers ديناميكياً قبل الحذف:** تبين أن `PRAGMA foreign_keys = OFF` لا يمنع قيود الحذف المطبقة برمجياً بواسطة الـ Triggers التي تستخدم `RAISE(FAIL, ...)` لمنع حذف السجلات المرحلة (مثل `trg_PreventDeletePostedDailyJournal`). لذلك تم إضافة جلب ديناميكي لكافة الـ Triggers وإسقاطها (`DROP TRIGGER IF EXISTS`) قبل البدء بعمليات الحذف، مع العلم أنها تُعاد بناؤها آلياً عند بدء تشغيل التطبيق في المرة القادمة عبر `MigrateDatabase()`.
3. **تصفية جداول النظام الداخلية:** استبعاد الجداول التي تبدأ بـ `sqlite_` (مثل `sqlite_sequence`) من حلقة الحذف المباشر لضمان استقرار محرك قاعدة البيانات، مع مسح `sqlite_sequence` بشكل مستقل.
4. **إغلاق مؤقت للقيود الخارجية (PRAGMA foreign_keys = OFF):** لتجنب فشل عمليات الحذف بسبب قيود المفاتيح الأجنبية وتكامل البيانات أثناء إفراغ الجداول.
5. **تأكيد الهوية عبر المصادقة الآمنة:** استخدام `IAuthenticationService` المعتمد لمطابقة كلمة مرور المستخدم الفعلي قبل تنفيذ المسح النهائي لمنع الإجراءات العشوائية.
