# سجل التمويل التشغيلي للشركاء (Partner Operational Financing Ledger)
*هذه الوثيقة تمثل الخطة المعمارية والمحاسبية المعتمدة لإعادة بناء وتشغيل وحدة "ديون الشركاء".*

---

## 1. الفلسفة المحاسبية والهيكل العام
تم تحويل الوحدة من مجرد "جدول ديون" إلى **سجل تمويل تشغيلي (Sub-Ledger)** للعمليات المالية بين المطعم وشركائه.
- **التصنيف المحاسبي للتسويات:** مرور تسويات سداد الشركاء عبر شاشة "المصروفات العامة" هو لتسهيل **سير العمل (Workflow)** فقط. لكن محاسبياً، تصنف تحت فئة `تسوية ذمم الشركاء`، وهي فئة لا تُحتسب ضمن مصاريف التشغيل الحقيقية في قائمة الدخل المعيارية، بل هي مجرد **تخفيض التزام (Liability Reduction)**.

---

## 2. النماذج البرمجية للبيانات الموحدة (DTOs & Enums)

**اتجاه الرصيد (Balance Direction):**
بدلاً من الاعتماد على السالب والموجب، يتم تحديد الاتجاه المعماري صراحةً:
```csharp
public enum PartnerBalanceDirection
{
    RestaurantOwesPartner, // المطعم مدين للشريك (أحمر/برتقالي)
    PartnerOwesRestaurant, // الشريك مدين للمطعم
    Settled                // تمت التسوية / صفر (أخضر/رمادي)
}
```

**نموذج سجل كشف الحساب الموحد:**
```csharp
public class PartnerStatementEntryDto
{
    public int SequenceNumber { get; set; }
    public DateTime TransactionDate { get; set; }
    public string TransactionType { get; set; }
    public string Description { get; set; }
    public decimal Amount { get; set; }
    public decimal RunningBalance { get; set; }
    public PartnerBalanceDirection BalanceDirection { get; set; }
    public string BalanceDirectionText { get; set; } // نص توضيحي للطباعة والواجهة
    public bool IsSettlement { get; set; }
    public string SourceType { get; set; }
    public int? SourceId { get; set; }
    public string ReferenceNumber { get; set; }
    public bool CanDelete { get; set; }
}
```

## 3. محرك الحسابات في طبقة الخدمات (OwnerDebtService)
لتأكيد فصل الواجهات عن منطق العمل، ولتسهيل التصدير وإعادة الاستخدام، **محرك حساب الرصيد التراكمي (Running Balance) يقع كاملاً في طبقة `OwnerDebtService`**.
- **دالة بناء الكشف `GetPartnerStatementAsync`:**
    - تجلب الديون والتسويات.
    - تدمجها وترتبها تصاعدياً حسب التواريخ.
    - تطبق حلقة دوران (Loop) لحساب الرصيد التراكمي لكل سطر في الذاكرة (On-The-Fly).
- **الإعادة التاريخية (Auto Historical Recalculation):**
    - إذا تم تغيير أي قيد أو تاريخ من المصدر (كالقيام بتعديل يوم سداد مورد قديم)، فإن الكشف يعيد ترتيب نفسه وتتحدث كل الأرصدة التراكمية التي تليه آلياً دون الحاجة لمزامنة يدوية.

---

## 4. نظام الوصف الذكي التلقائي (Smart Description Engine)
تُستنتج الأوصاف من `SourceType`:
- **الموردين:** "سداد فاتورة مورد: [اسم المورد]"
- **المصروفات العامة:** "مصروف تشغيلي ([فئة المصروف]) مدفوع بواسطة الشريك"
- **تسويه مباشرة:** "تسوية ذمة مالية للمطعم عبر [وسيلة الدفع]"

---

## 5. تصميم الواجهات (UI/UX)
**أ. لوحة المتابعة الرئيسية (Dashboard)**
- تعتمد على عرض الكروت (Cards) بترتيب أبجدي لأسماء الشركاء.
- الكرت يتضمن: (اسم الشريك، الرصيد الحالي المباشر، لون الحالة).
- يبقى الشريك ظاهراً في الداشبورد حتى لو وصل رصيده إلى (صفر).

**ب. نافذة كشف حساب الشريك (Statement Window)**
- **البطاقات العلوية الإحصائية:** 
  1) إجمالي التمويل (ما دفعه الشريك).
  2) إجمالي التسويات (ما سدده المطعم).
  3) الرصيد الصافي الحي.
  4) عدد العمليات المنفذة.
- **جدول الحركات (DataGrid):** تصميم بنكي متقدم، يحتوي على عمود "الرصيد التراكمي" البارز، مع تلوين المبالغ دلالياً وتظليل الأسطر.

---

## 6. استراتيجية الأداء والتحديث (Performance & Connectivity)
- **داشبورد فائق السرعة:** جلب الأرصدة يتم من خلال `Aggregation Queries` مباشرة في الاستعلام (بدون تحميل كامل البيانات) ومع استخدام `AsNoTracking()`.
- **التحديث الحي المتباعد:** استخدام `WeakReferenceMessenger` (الخاص بـ `CommunityToolkit.Mvvm`).
  - *مثال:* عند قيام مستخدم بإضافة الدفع لشريك من شاشة (الموردين)، تنطلق رسالة صامتة تخبر (داشبورد الشركاء) بتحديث الإجماليات في الخلفية لتجنب (Freeze) واجهة المستخدم.

---

## 7. الحماية وشروط النزاهة المالية (Data Integrity & Safety)
- **عنونة الحذف:** ميزة الحذف (`CanDelete`) تكون مسدودة (False) متى كان السجل قادماً من عملية تشغيلية (`SourceId != null`).
- عند محاولة الشطب، يتم عرض رسالة قانونية: *"لا يمكن إزالة قيد مالي تشغيلي من الكشف؛ الرجاء تعديل أو حذف المستند المصدر (كمصروف عام أو فاتورة مورد) لضمان اتساق القيود المحاسبية."*
